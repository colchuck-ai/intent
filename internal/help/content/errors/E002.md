# E002 — inline/document containment

**Cause.** An element with `type: document` has a parent that is still `inline`.
A document renders to its own file, which needs a folder to live in — and an
inline parent has no folder. Document-ness must be connected from the root down.

**You should almost never see this.** The CLI keeps containment valid by
construction: `intent promote <addr>` (and `set <addr> type document`)
auto-promotes every inline ancestor in one step, like `mkdir -p`. E002 only
appears when `intent.yaml` was hand-edited into the invalid state.

**Fix.**

- Preferred: re-run the promotion so ancestors cascade —
  `intent promote <addr>`.
- Or promote the specific parent the error names.
- If the child shouldn't be a document after all, demote it:
  `intent set <addr> type inline` (add `--cascade` if it has document
  descendants).

See also `intent help judgment:altitude` for whether the element deserves its
own page at all.
