# E001 — dangling reference

**Cause.** Something points at an element that isn't in the tree. This covers
two cases:

- a declared edge (`mitigates`, `fulfills`, `dependsOn`, `affects`,
  `relationships`) whose target address doesn't resolve, and
- a prose `{{ }}` interpolation (in `statement`, `story`, `detail`, a
  component's `behavior`, etc.) whose address doesn't resolve.

Both are the same failure: a reference to nothing. Prose links never create
trace edges, but they must still point at a real element.

**Common reasons.** The target was renamed or moved (its address changed), the
target was removed, or the address has a typo.

**Fix.**

- Find the right address: `intent find <words from the name>` or `intent tree`.
- If it's a declared edge, repoint it: `intent unlink <kind> <from> <old>` then
  `intent link <kind> <from> <new>`.
- If it's a prose address, `intent set <addr> <field> "<corrected prose>"`.
- If the target genuinely shouldn't exist, remove the reference.

Because `mv` and `rm` cascade references across the whole tree, a dangling edge
usually means the target was hand-edited or deleted outside the CLI — prefer the
CLI so this can't happen.
