# E003 — duplicate reference in a list

**Cause.** One edge list (`mitigates`, `dependsOn`, `fulfills`, or a record's
`affects`) names the same target address twice. An edge either exists or it
doesn't; listing it twice says nothing extra and makes the diff noisier.

`relationships` is exempt — it's a keyed map, so duplicate keys can't occur.

**Fix.**

- Remove the extra copy: `intent unlink <kind> <from> <to>` removes the edge;
  re-add it once with `intent link <kind> <from> <to>` if needed.
- Using `intent link` in the first place prevents this — it's a set operation
  and won't add a target that's already present.
